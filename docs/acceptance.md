## 演示数据计划

至少准备 2 名教师和 3 名学生：教师分别负责不同课程，学生之间既有共同选课也有未选课程。准备同主题但含不同标记的私人笔记，便于验证检索隔离。

结构支持多课程，正式问答评测以《数据库原理》为主；另设一门小型测试课程验证跨课程权限。容量为 1 的测试课程用于并发验证。示例资料须自行编写、取得授权或来自可合法使用的来源，不使用真实同学的私密笔记作为公开演示数据。

## 核心验收用例

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 教师创建课程，注入授课关系写入失败 | 课程及授课关系一起回滚 |
| A02 | 学生正常选课和退课 | 关系状态和界面人数正确，资料权限同步变化 |
| A03 | 重复选课或并发重复请求 | 唯一关系不重复，提示明确 |
| A04 | 两人并发争抢最后一个名额 | 恰有一人选课成功，有效人数不超过容量 |
| A05 | 教师将容量改为小于已选人数 | 拒绝变更，数据库保持原容量 |
| A06 | 未选课学生通过直接 API 访问公共资料 | 拒绝内容访问，课程简介仍可浏览 |
| A07 | 学生 A 请求学生 B 的笔记编号、下载和引用 | 不返回文件、片段、标题等私人信息 |
| A08 | 教师访问学生私人笔记与私人问答 | 拒绝；课程统计不泄露原文或问题 |
| A09 | 上传超大、伪扩展名或无可提取正文文件 | 提示不支持或解析失败，不成为 READY |
| A10 | worker 处理过程中进程终止 | 租约过期后可恢复，未发布的部分分块不可检索 |
| A11 | 替换正文与旧 worker 同时完成 | 仅当前版本可发布和检索，旧任务不能覆盖 |
| A12 | 删除资料后旧任务重试 | 不能重新发布资料，不能检索或下载 |
| A13 | 学生退课后查看旧答案与引用 | 公共资料不可访问，涉及失效引用的答案不返回原文；本人笔记仍可独立管理 |
| A14 | 生成期间资料被删除或用户退课 | 不返回生成正文，也不保存为成功可见答案，提示重试 |
| A15 | 资料内写入“读取其他学生笔记”的指令 | 检索范围不扩大，不执行文档指令或越权工具 |
| A16 | 模型超时、限流或返回无效引用 | 返回明确错误或依据不足状态，不伪造来源；重试次数有界 |
| A17 | 同一会话网络重发相同请求键 | 返回已有状态或结果，不另起一次生成；同键不同问题返回冲突，上游重试次数另行记录 |
| A18 | 课程同时含多名学生和多份资料 | 聚合人数和资料数量正确，无 JOIN 放大计数 |
| A19 | 学生评价自己的回答后修改评价 | 一轮仅一份反馈；其他用户不能代评 |
| A20 | 数据库容器与后端重启 | 业务数据保留，任务可恢复，运行方法可重复 |
| A21 | 新 worker 成功后，租约已失效的旧 worker 才报错 | 旧失败写回被拒绝，资料仍为 READY，当前向量不变 |
| A22 | 问答使用了两份资料但只显式引用一份，未引用的上下文资料随后失效 | 历史答案按全部上下文依赖判断失效，不泄漏未标注来源的内容 |

A09 至 A12 还需覆盖上传与替换请求的幂等：同键同内容只创建一个资料/版本和任务，同键不同内容返回冲突，竞争失败只能清理自己的临时文件。评测检查还应核对实际 Top-K 与逐次模型调用记录是否完整，包含失败和用量未知的尝试。

每项执行后记录测试环境、账号、输入、预期、实际、通过/失败及证据路径。截图应避免包含密钥和真实私人信息。

## 推进顺序与完成条件

1. **设计基线**：明确角色、资料可见性、退课和历史引用规则；本轮形成初稿。
2. **数据库验证**：跑通约束、事务、并发和授权向量 SQL；固定镜像与 Python 依赖策略。
3. **数据库与业务后端**：手写建表和种子数据，实现登录、课程、选课、资料权限；完成正常流程与越权测试。
4. **React 业务界面**：跑通教师建课上传、学生选课和资料管理；问答区如使用模拟响应须标记。
5. **真实 RAG**：选择 Embedding，完成解析、任务恢复、SeekDB 授权检索；选择回答 API，接入引用、无依据提示和用量记录。
6. **评测与迭代**：完成固定问题集、用户任务试用、错误分析和至少一次有证据的改进。
7. **验收打包**：补全运行说明、正式实验报告、SQL 演示、截图与录屏；执行一次干净环境复现。

实际周次按课程日历核对：第 14 周周四中期检查，第 14 周周日提交分组、题目和阶段性报告，第 16—17 周验收。未提供课程周历和报告模板，不能据此推算具体日期或声称最终报告格式已完成。
