# 转账示例的检索与回答依据规则

日期：2026-11-25。状态：初始产品规则，尚未接入真实检索或模型验证。

## 用户参与的决定

讨论使用自行编写的 A、B、C、D 四份资料，问题为“为什么转账不能只扣钱，不加钱？程序中途出错怎么办？”。

1. 用户选择 A、B 作为理想相关资料：A 解释事务原子性，B 提供转账例子。
2. 首轮只有 A 时，用户选择先补充检索，尝试找到转账步骤、失败与回滚的资料。
3. 补查后仍只有 A，用户选择依据 A 回答，引用 A，不编造已找到 B 的说法。

这些是特定示例的预期行为。D 属于其他学生私人资料，必须在每轮检索前排除，这一要求来自实验权限约束。C 可访问但不相关。

## 人工拟写的回答示例

> 转账的扣款和入账应作为同一事务执行。事务内的操作要么全部成功，要么全部回滚；因此程序中途出错时，应一起回滚，避免只完成扣款。[A]

这是将 A 的原子性原则用于解释问题，不将转账例子冒充课件原句。它不是模型生成结果，也不是唯一允许的答案措辞。

## 对实现与验收的影响

- 检索理想结果为 A、B；回答中实际依据与引用必须匹配。
- 每轮查询都使用当前有权访问的候选范围，补查不能扩大权限。
- 补查应围绕缺失信息调整查询，而不是无条件重复同一次请求；具体策略等待检索实验确定。
- 最多额外一轮是助手提出的实验默认值。用户明确选择了补查与回答行为，未单独确认轮数；上线标准需要结合相关性、耗时和成本再验证。
- 只找到 A 时，检索覆盖不理想与回答可接受可以同时成立，不能只看最终回答流畅程度判断检索成功。
