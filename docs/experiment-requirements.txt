本实验要求学生综合运用数据库课程所学知识，设计并实现一个以数据库为核心、具有完整业务流程的应用系统，并在此基础上使用 SeekDB 增加一项与业务紧密结合的智能功能。

核心原则：数据库应用是主体，智能功能是增强。 不能仅将现有 SeekDB 示例加上网页界面，也不能用与业务数据无关的独立聊天窗口代替智能功能。

完成实验后，应能够：
1. 进行需求分析，设计 ER 图和关系模式，合理设置主键、外键、约束及索引；
2. 编写 SQL 建表与数据操作语句，实现增、删、改、查、多表关联查询及统计查询；
3. 实现完整业务流程，合理运用事务保证相关数据更新的一致性；
4. 实现用户登录、角色权限与数据访问控制，妥善处理业务异常；
5. 将 SeekDB 的向量检索、RAG 或语义检索应用到实际业务场景，构建可操作、可演示的系统。
完成实验 0：环境配置与向量入门，了解 SeekDB 基本使用方法，完成数据增删改查与简单向量检索。

题目描述： 设计一个面向图书馆或图书借阅室的管理系统，实现图书、读者及借阅业务管理，并通过 SeekDB 提供智能找书服务。

1. 基本业务功能
1. 图书管理： 录入、修改、删除和查询图书信息，包括编号、书名、作者、类别、简介、馆藏及可借数量等。
2. 读者管理： 维护读者信息、借阅资格和借阅记录。
3. 借阅与归还： 支持借书、还书、续借；同步维护可借数量及借阅状态。
4. 综合查询与统计： 按名称、作者、类别等条件查询；统计热门图书、借阅数量和逾期情况等。
5. 用户权限： 区分管理员与普通读者。管理员管理图书和借阅业务；普通读者只能查看允许公开的图书信息及自己的借阅记录。
6. 异常管理： 处理库存不足、重复借阅、借阅数量超限、逾期、图书丢失或损坏、重复归还等情况；借还书相关更新应保证事务一致性。
2. 智能功能

利用 SeekDB 对图书标题、简介或主题进行语义检索。例如，用户输入“推荐有关人工智能与未来社会的科幻小说”，系统返回相关图书，并结合数据库中的馆藏状态展示是否可借。可以扩展相似图书推荐与结构化过滤。

3. 数据库设计提示

可包含图书、作者、类别、读者、借阅记录等关系表；明确各表之间的关联，提供相应建表 SQL、约束、多表查询和借还书事务。

推荐教程： 实验 3（中文语义查询）。
题目描述： 设计一个面向师生的课程管理与学习平台，实现课程、选课及教学资料管理，并将教师公共资料与学生个人资料结合起来提供 RAG 问答服务。

1. 基本业务功能
1. 用户管理： 支持教师、学生等角色登录和个人信息维护。
2. 课程与选课管理： 教师管理课程；学生浏览、选课、退课、查看已选课程；支持课程容量等业务约束。
3. 教师资料管理： 教师可以为自己管理的课程上传、修改、删除课件、教学大纲、实验指导书等课程公共资料。
4. 学生资料管理： 学生可以在相关课程下上传、修改、删除和查询自己的笔记、学习资料等。
5. 查询与统计： 支持课程和资料的条件查询，以及选课人数、课程资料数量等统计。
6. 用户权限： 教师只能管理自己负责课程的教学资料；学生只能访问有权查看的课程资料和自己的个人资料，不能访问其他学生的私人资料。
7. 异常管理： 处理重复选课、课程容量不足、未选课访问受限内容、无权限修改或删除文件、文件类型或大小不合规、上传失败等问题；确保选课状态和课程容量统计一致。
2. 智能功能

基于 SeekDB 实现 RAG 课程问答。学生提问时，系统同时检索：
- 该学生有权限访问的教师上传的课程公共资料；
- 该学生自己上传的个人学习资料。
系统使用检索内容生成回答，并展示引用来源。例如：“结合老师的课件和我上传的笔记，解释 BCNF 与 3NF 的区别。”

重点要求： 必须对检索候选资料进行权限限制，不能先检索其他学生的私人资料、再仅依靠大模型提示词隐藏。资料删除或权限变化后，应及时更新检索可见性，避免越权引用。

3. 数据库设计提示

可包含用户、教师授课关系、课程、选课记录、资料、文档分块、问答记录等关系表，体现课程与资料的关联，以及资料所有权和访问权限。

推荐教程： 实验 1（RAG 检索增强生成）。
题目描述： 设计一个宠物店业务管理系统，支持宠物信息管理、客户管理、购买或预约等业务，并利用 SeekDB 实现以图搜宠物。

1. 基本业务功能
1. 宠物信息管理： 记录宠物编号、品种、年龄、性别、图片、价格、健康备注及在售／已售等状态。
2. 品种与分类管理： 维护宠物品种和分类信息。
3. 客户管理： 实现客户资料的录入、修改和查询。
4. 销售或预约管理： 实现宠物购买、领养或服务预约等至少一种完整业务流程，并维护订单或预约记录。
5. 查询与统计： 支持按品种、价格、年龄、状态筛选，并统计宠物数量、品种分布与销售或预约情况。
6. 用户权限： 区分店员／管理员与普通客户；客户只能查询公开宠物信息并管理自己的订单或预约，店员／管理员管理宠物和业务记录。
7. 异常管理： 处理宠物已售、重复下单或预约、取消预约、无效价格、图片缺失或不支持的格式等；关键业务操作应避免重复销售与状态不一致。
2. 智能功能

利用 SeekDB 实现以图搜图：用户上传一张猫或狗的图片，系统查找店内外观相似的宠物，展示品种、价格与在售状态；支持结合品种、价格、状态等条件筛选结果。

建议使用实验 2 的宠物图片数据作为入门材料，再自行构造或收集与宠物店业务相对应的图片和宠物记录。检索结果必须关联实际宠物业务数据，不能只展示原实验的图片 Top-K 列表。

3. 数据库设计提示

可包含宠物、品种、宠物图片、客户、订单或预约等关系表，设计相应约束及业务处理事务。

推荐教程： 实验 2（图像搜索）。
题目描述： 面向小型商店或仓库设计一个商品与库存管理系统，完成商品、供应商、出入库等业务管理，并增加智能商品搜索能力。

1. 基本业务功能
1. 商品管理： 实现商品信息、分类、价格、图片等内容的录入、修改、删除和查询。
2. 供应商管理： 管理供应商信息及供货关系。
3. 库存管理： 实现采购入库、销售出库或领料出库等业务，维护库存数量及出入库记录。
4. 综合查询： 按商品名称、类别、价格区间、库存情况等条件查询。
5. 统计与预警： 实现库存数量统计、出入库汇总，以及库存不足提醒。
6. 用户权限： 区分管理员、仓库操作员、普通查询用户等角色，限制商品修改、库存调整和出入库操作权限。
7. 异常管理： 处理库存不足、重复出入库、非法数量、退货、商品信息无效等情况；库存变更与出入库记录应在同一事务中保持一致。
2. 智能功能（二选一）
- 方向 A：商品图像搜索。 用户上传商品图片，系统查找外观相似的商品，结合价格、分类和库存状态过滤。
- 方向 B：商品语义搜索。 用户输入自然语言需求，例如“适合宿舍使用的便携小台灯”，系统检索相关商品，并提供价格、库存等信息。
数据准备： 学生自行准备一定数量的商品信息、简介和图片，可以使用公开商品页面、开放数据集等合法合规的数据来源。若从电商平台采集，应遵守平台规则、版权要求和访问限制；不要求绕过反爬机制，不使用真实用户的个人信息。

3. 数据库设计提示

可包含商品、类别、供应商、库存、入库单、出库单或出入库明细等关系表，重点考虑多表查询和库存变动的一致性。

推荐教程： 方向 A 参考实验 2（图像搜索）；方向 B 参考实验 3（中文语义查询）。
- 完成需求分析，明确系统的主要用户角色、业务对象和业务流程；
- 绘制 ER 图，转换为关系模式，说明关键属性、主键、外键和约束；
- 设计至少 3 张存在实际关联的业务表，自行编写 SQL 建表语句；
- 实现数据的增加、删除、修改、查询，以及至少一项多表 JOIN 查询和一项聚合统计查询；
- 根据查询场景合理设计索引，并说明索引的作用；
- 对多步骤业务操作合理使用事务，并展示至少一个需要保证数据一致性的业务场景。
- 系统应具备实际可操作的业务流程，不得只运行独立脚本或静态展示数据；
- 提供可交互的应用界面，Web（B/S）或桌面程序（C/S）均可；
- 提供测试数据和可重复的系统运行方法；
- 必须实现用户身份与权限管理：至少区分两类实际业务角色，限制不同角色可执行的操作与可访问的数据；
- 必须实现异常处理：对非法输入、重复操作、无权限操作、业务约束冲突、数据不存在、关键步骤失败等情况，给出合理提示并确保数据库状态正确；
- 关键数据库操作不得仅通过前端限制权限或校验输入，应在服务端／数据库操作层落实检查。
- 结合选做的实验 1、2 或 3，实现与业务相关的 RAG 问答、图像搜索或语义检索；
- 智能功能必须读取并关联本系统实际管理的业务数据，不能与业务系统完全独立；
- 检索结果应能够显示必要的结构化业务信息，如类别、状态、价格、所属课程、权限等；
- 业务数据新增、修改或删除后，应合理维护对应的检索数据，避免明显过时或无效的结果；
- 涉及私有数据时，检索与回答过程必须遵守用户权限限制。
技术实现说明： 原 SeekDB 入门教程主要使用 pyseekdb 的 Collection API；综合应用还要求关系表、SQL 和事务。应使用支持相应 SQL 能力的数据库访问方式。可以优先采用 SeekDB 的 SQL 能力，或在教师认可的前提下使用关系型 DBMS 负责业务数据、SeekDB 负责智能检索，但必须说明两者的数据关联和同步方式。不能用 Collection 的 metadata 字段代替全部关系模式设计。
