# 课程学习助手产品需求初稿

版本：0.1。日期：2026-11-24。

目标是在满足数据库实验要求的基础上，交付一个可操作、可测试的课程学习产品，并保留需求、设计、评测与迭代证据。以下用户问题是待验证的产品假设，不能作为已完成的用户调研写入报告或简历。

## 用户问题与核心流程

假设学生在复习时需要来回查找课件、实验指导书和个人笔记，希望得到能够核对原文的解释。教师需要维护课程公共资料，并了解课程和资料使用情况。

核心流程：教师创建课程并发布资料 → 学生选课 → 上传私人笔记 → 在课程内提问 → 核对引用 → 评价回答。

首轮调研建议访谈约 5 位同学，记录最近一次查找课程资料的任务、现有操作、耗时、错误与资料来源，确认是否值得优先解决。当前尚未开展访谈。

## 首版范围

| 必须交付 | 行为 |
| --- | --- |
| 登录与个人信息 | 使用初始化账号登录，修改自己的显示信息和密码；教师身份不能通过公开注册获得 |
| 课程与授课关系 | 教师创建、查看、修改自己负责的课程，设置容量和开放状态 |
| 选课与退课 | 学生浏览可选课程、选课、退课、查看当前选课；处理重复选课和容量不足 |
| 教师公共资料 | 任课教师上传、替换、修改标题、删除课程资料；有效选课学生可访问 |
| 学生私人笔记 | 学生在已选课程上传、替换、修改标题、删除自己的资料；其他用户不可访问 |
| 课程问答 | 单轮问题结合课程公共资料与本人笔记，展示答案和可核对的引用；保留历史 |
| 统计与反馈 | 教师查看课程选课人数、公共资料数量；学生评价自己的回答并选择问题类型 |

首版暂不包含开放注册、管理员后台、批改作业、自动出题、学习计划、联网搜索、语音和多 Agent。问答历史用于查看，首版不自动拼接整段历史参与生成。

文档输入先支持文本型 PDF、TXT、Markdown；初始建议每份最多 10 MiB。扫描件、图片、PPTX、DOCX 后续按真实需求扩展。遇到无可提取正文的文件应明确提示，不能显示为可检索成功。大小上限属于初始产品配置，可在开发验证后调整。

## 角色权限

权限以服务端身份、当前授课/选课关系和资料状态为依据。前端传来的用户编号、角色和可见范围不能作为授权依据。

| 操作或数据 | 学生 | 教师 |
| --- | --- | --- |
| 浏览开放课程的简介 | 可以 | 可以 |
| 创建课程 | 不可以 | 可以，同时建立本人授课关系 |
| 修改课程、调整容量、管理公共资料 | 不可以 | 仅限本人负责课程 |
| 选课、退课 | 仅操作自己 | 不作为学生选课 |
| 课程公共资料内容 | 仅有效选课课程 | 仅本人负责课程 |
| 上传私人笔记 | 仅有效选课课程 | 首版不支持 |
| 查看、下载、删除私人笔记 | 仅本人所有；退课后仍可在“我的资料”管理已有笔记 | 不可以查看学生私人笔记 |
| 替换私人笔记正文 | 仅本人所有且课程选课有效 | 不可以 |
| 课程问答 | 仅有效选课课程的公共资料和本人笔记 | 仅本人负责课程的公共资料 |
| 问答历史和回答反馈 | 仅本人 | 仅本人，不查看学生私人问答 |
| 课程统计与名单 | 查看本人选课状态 | 仅本人负责课程的选课名单和业务统计 |

教师上传的“公共资料”表示对该课程有权限的人公开，不表示向全站或互联网公开。

角色首版为互斥的 STUDENT / TEACHER；同一账号暂不兼任。账号停用后不得通过既有会话继续访问。

## 边界规则

1. 退课即时撤销课程公共资料及课程问答权限；已有私人笔记仍归本人所有，但不能继续用退课课程发起问答。重新选课后恢复相应范围。
2. 学生始终不能访问同学笔记，教师也不能通过统计、文件下载或问答访问学生私人内容。
3. 课程容量不能设置为小于当前有效选课人数。关闭选课只阻止新增选课，不撤销现有学生资料权限。
4. 存在有效选课、资料或问答历史的课程不能直接硬删除。首版通过关闭选课管理存量课程；删除只允许没有关联业务数据的课程。
5. 替换资料正文时先使旧版本退出新问答检索，显示“处理中”；新版本处理成功后才重新可检索。失败显示原因并允许重试。
6. 删除资料后立刻禁止新检索和下载。文件及旧分块可以延后清理，不能依赖清理完成才撤销访问。
7. 历史答案可能包含已失效资料的内容。保存全部实际发送给模型的证据片段及版本，不只保存模型最终标出的引用。服务端每次读取历史时检查全部上下文依赖的版本、删除状态和当前权限；有任意依赖失效则整条答案暂不展示，显示“依据资料或权限已变化，请重新提问”。问题文本和时间仍可展示。
8. 当前资料不足以回答时提示补充资料或调整问题；模型服务失败时显示失败状态，保留问题并允许显式重试，不生成伪造答案。

上述退课、历史答案和文件上限规则是首版设计默认值，后续可以基于试用反馈调整。

## 页面结构

| 路由草案 | 页面与主要交互 |
| --- | --- |
| `/login` | 登录、错误提示 |
| `/courses` | 课程列表、条件筛选、学生选课/退课；教师创建课程 |
| `/courses/:courseId` | 课程工作台：资料区、问答区、引用区 |
| `/courses/:courseId/manage` | 教师管理课程、容量、公共资料、选课名单和统计 |
| `/materials` | 我的上传资料，查看处理状态、重试、替换和删除；学生可管理退课后的已有笔记 |
| `/history` | 本人问答记录及引用失效提示 |
| `/settings` | 本人信息和密码 |

课程工作台：左侧区分“教师资料”和“我的笔记”，中间展示问题与回答，右侧查看所选引用原文。引用正文、文件名、可获得的页码或 Markdown 标题均从实际资料解析信息获得，不由模型编造。

关键状态：未选课、无资料、资料处理中、处理失败、问答生成中、无充分依据、模型调用失败、引用失效。首版采用后端完整生成后返回；前端展示等待状态，稍后再决定是否引入流式传输。

## 产品评测

先建立 30—50 道真实课程问题的评测集，包含概念解释、多资料对照、资料中没有答案、私人笔记权限隔离以及已删除资料等类型。每题记录可访问用户、课程、参考资料片段和判分规则。

| 指标 | 评测方式 |
| --- | --- |
| 检索命中 | 标注相关片段是否进入 Top-K，按题统计；相关片段需人工标注 |
| 回答正确与依据充分 | 按明确评分规则人工检查答案和检索材料 |
| 引用准确 | 引用实际存在、可访问，并支持相应结论；技术校验和人工核对分开统计 |
| 无依据回答行为 | 无答案题是否说明不足，是否编造课程资料结论 |
| 用户任务完成情况 | 用相同任务对比现有找资料方式和助手；记录完成时间及是否完成 |
| 延迟与成本 | 按实际请求记录总耗时、检索/生成耗时、Token 用量和估算模型费用 |

首轮比较关键词检索与向量检索；基线完成后，再验证混合检索、分块参数或回答模型的调整。保留独立验收问题，避免只对调参问题过度优化。

访谈人数、题量、提升幅度及满意度等只有完成真实采集后才能作为项目成果。未经实测不承诺准确率或效率提升。
