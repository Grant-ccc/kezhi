# 第一条真实向量检索实验

日期：2026-11-25。范围：独立临时库上的单条自编用例，未接入正式问答页面。

## 问题与事先预期

问题为“为什么转账不能只扣钱，不加钱？程序中途出错怎么办？”。用户在模型实验前选定 A/B 为理想资料集合，不要求顺序；C 为可访问但不相关资料，D 为其他学生的私人笔记。原始题目、资料与 Top-K=2 均未因本次结果修改。

## 已实现

- 提取独立 SQL 检索模块。候选检查和精确排序共用权限条件，在 SQL 的 WHERE 中检查账号状态、有效选课/授课关系、私人笔记所有权、课程、READY、未删除、当前版本、当前片段、向量存在及模型 profile，然后进行距离排序和 LIMIT。
- 实验运行器使用项目 001_schema.sql 创建完整业务表，将 A/B/C/D 映射为用户、课程、选课、资料和分块记录，并在临时库增加向量列。只有实验夹具直接置 READY；正式 worker 仍不发布向量。
- 真实模型每次实验最多两次请求，无自动重试。先准备数据库，再调用模型。复用同批向量执行可见性变体，不增加模型调用。
- 默认命令不联网；--live 显式启动。随机命名的临时库在 finally 中清理，独立结果文件保留调用摘要、来源、fixture 哈希及清理状态，不保存密钥或完整向量。

## 真实运行结果

使用百炼 qwen3.7-text-embedding、1024 维、query/document 角色、原始向量及 SeekDB 1.4.0 的 cosine_distance 精确查询，完整结果见 [运行 JSON](../../evals/results/20261125T062724403530Z-retrieval-v0.1.json)。

| 学生 A 的排名 | 资料 | 含义 | 余弦距离 |
| --- | --- | --- | --- |
| 1 | B | 自己的转账操作笔记 | 0.298308 |
| 2 | A | 教师的事务原子性说明 | 0.546227 |

候选只有 A/B/C，D 在取 Top-K 前被过滤。两条预期资料均找到，单题 Recall@2=1、Precision@2=1。只有一道自编问题，不能推广为整体正确率。余弦距离表示向量接近程度，不是可信度或答案正确概率。

四份资料一批调用报告 163 Token、1022 ms；问题调用报告 31 Token、1327 ms。总报告用量 194 Token，实际扣费未查询。候选检查及排序两次 SQL 合计 33 ms，为本机单次观测，不能当作性能承诺。临时库已成功清理，业务库没有修改。

13 个可见性变体全部通过：删除标记、删除状态、替换版本、非当前片段、不同 profile、PARSED 未 READY、跨课程、退课、禁用账号、教师看不到学生笔记、另一个学生只能看自己的笔记、未选课学生、未授课教师。每次变体回滚后才执行下一项。

## 产品发现与边界

移除 B 后，固定 Top-K 仍返回两条：A 和不相关的 C。因此返回片段数量不能代替“依据充分”。没有凭这道题设定全局距离阈值，没有实现自动补查或调用 DeepSeek。资料不足时的产品行为正在邀请用户参与选择，待确认后再记录并实现。

用户随后确认：资料无法支持天气问题时，提示资料不足并建议换题或补充资料，见 [决策记录](../decisions/003-insufficient-evidence.md)。新增第二条人审预期，尚未实现或运行；并未纳入本次模型检索成绩。

本阶段验证实际模型与 SQL 的组合及指定状态下的过滤。没有验证正式 HTTP 身份入口、资料向量发布、生成时并发撤权后的再次校验、引用或历史权限；正式业务库仍没有向量列，worker 仍止于 PARSED。
