# 课程学习助手评测样例

cases 目录保存产品共建中的人工示例和预期结果，results 目录保存实际运行记录。目前完成一条自编用例的真实百炼 Embedding + SeekDB 检索实验，不代表真实用户调研或完整 RAG 效果。

## 第一条检索用例

[retrieval-v0.1.json](cases/retrieval-v0.1.json) 包含一道转账与事务的问题、四份自行编写的资料以及学生的访问范围。用户在讨论中选择 A、B 作为应返回的相关资料，因此记录为预期集合，不强制 A/B 顺序。

- A 解释事务原子性，B 将原理应用于转账，两者互补。
- C 属于可访问的课程资料，但与该问题不相关。
- D 与问题相关，但属于其他学生的私人笔记，必须在检索候选范围中排除。这个权限要求来自实验要求，不因语义相似而放宽。

运行器将这些逻辑身份映射到独立临时库中的真实业务表记录，再通过带权限条件的 SQL 取候选与排序。评测同时检查实际候选范围和返回片段；当前未接入 HTTP 登录入口、正式资料向量发布或回答模型。

## 第一轮真实结果

[2026-11-25 运行记录](results/20261125T062724403530Z-retrieval-v0.1.json)：学生 A 的候选是 A/B/C，返回顺序为 B、A，D 在候选中即被排除。两条预期资料均被找回，本题 Recall@2 与 Precision@2 均为 1；样本数只有 1，不能称为系统准确率或实际课程效果。

使用原始题目与原始四份自编文本，没有根据结果改写问题或调参。向量由真实百炼接口生成，1024 维，四份资料一批、问题一批，共两次请求，报告用量 194 Token。检索由 SeekDB 1.4.0 执行余弦距离精确排序，未采用 Python 相似度排序；距离不是答案正确概率。

复用同批真实向量验证了 13 个可见性变体：逻辑删除、删除状态、版本替换、非当前片段、不同模型配置、未 READY、跨课程、退课、禁用账号、教师排除私人笔记、其他学生只见自己的笔记、未选课学生、未授课教师。通过范围限于这些 SQL 状态，不能代替正式上传、登录授权及并发变更的端到端验收。

当 B 不再可见时，返回 A、C。这说明固定取两条也会带回不相关资料；是否有足够回答依据仍需单独设计和评测。当前没有设置凭本题拟合的距离阈值，也没有验证自动补查或资料不足时的回答行为。

## 重复运行

数据库与百炼配置就绪后，从仓库根目录执行：

```powershell
Push-Location backend
..\.venv\Scripts\python.exe -m app.evaluation.retrieval
# 上一条默认不联网。下列 --live 才创建实验库并进行两次真实模型调用，可能计费。
..\.venv\Scripts\python.exe -m app.evaluation.retrieval --live
Pop-Location
```

只发送本文件关联的四份自编资料和一个问题，不读取上传目录；不会自动多轮、重试或调参。先验证本机数据库和表结构，再调用 API。使用项目 root 配置创建随机命名的独立临时库，只删除自己成功创建的库，不向业务库写入向量。成功和失败均尝试清理，结果中的 temporary_database_cleaned 用于核对清理；失败不代表未计费。

运行结果按 UTC 时间生成新文件，保留已完成调用的请求编号和实际返回用量，不含密钥、空间 ID 或完整向量。失败请求若没有用量则不能推算为免费；账单为准。自动测试使用明确标注的合成向量替身，不把这类测试计入真实模型效果。

## 已共同确定的补查与回答规则

用户选择：这道题首轮只找到 A 时，先补充检索转账相关资料；补查后仍只有 A，则根据 A 提供有边界的回答，只引用实际找到的资料，不声称读过 B。已记录到 followup_policy，决策说明见 [回答依据规则](../docs/decisions/001-answer-evidence.md)。

该规则限于当前示例，不是全局“资料少于两份就必须补查”。最多额外一轮是助手提出的实验默认值，并非用户明确选定的数字，也未做耗时或效果验证。查询策略、如何判断依据充分，以及完全没有可用资料时的处理仍待制定。

检索与回答分开评价：只返回 A 没有达到理想资料覆盖，但依据 A 的正确解释仍可能满足回答要求。人工示例答案用于说明预期，不是模型运行结果，也不要求模型逐字复述。
